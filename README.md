# ThinkTogether

**Учебная платформа: персональный маршрут, самостоятельная практика, постоянные группы и AI-авторинг курсов.**

Репозиторий: [Feruum/zimranhack](https://github.com/Feruum/zimranhack), основная ветка — **main**. ThinkTogether объединяет редактор курсов, аккаунты, персональное обучение, совместную практику и инфраструктуру LMS.

Документ описывает реализованный код и подтверждённые локальные проверки на **15 ноября 2026 года**. Платный PMP-пилот остаётся закрытым до выполнения условий запуска: наличие кода не заменяет утверждение программы, реальные группы и проверку внешних сервисов.

## Что сделано

Первый продуктовый сценарий — подготовка взрослых кандидатов к PMP с диагностикой, объяснимым личным планом и постоянной группой. Планируемый первый пилот — до четырёх групп, до 24 участников; это продуктовый масштаб пилота, а не подтверждённый предел производительности.

| Область | Реализация |
|---|---|
| Основа LMS | Сохранены аккаунты, организации, курсы, главы, материалы, редактор Tiptap, библиотека и модули LMS |
| ThinkTogether Core | Today, программа, практика, группа, прогресс, профиль, коммерческий доступ и рабочее место эксперта |
| Контент | Версии программ, навыков, уроков, заданий, рубрик, диагностик и пробных экзаменов; импорт, проверка и экспорт пакетов |
| Диагностика | Отдельные предметные и когнитивные инструменты, согласия, приватные результаты, проверка специалистом |
| Адаптация | Попытки, подсказки, история оценок, свидетельства освоения, повторения и план с ограничением времени |
| Группы | Постоянные cohorts на 4–6 человек, совместимость расписаний, членство, обсуждения и календарь |
| Комнаты | Серверные фазы, личные попытки, чат, SSE, совместная доска и контроль медиаправ |
| AI-авторинг | Материалы → структура → главы → упражнения → сохранённые черновики → экспертная проверка |
| Коммерция | Собственный Polar-контур: checkout, резервы мест, webhook, доступ, возвраты и сверка |
| Фоновые процессы | PostgreSQL outbox, Celery, Redis, scheduler, leases, retries и восстановление заданий |
| Эксплуатация | Docker Compose, production-шаблоны, миграции, backup/restore, CI и выдача соответствующего исходного кода |
| Безопасность | Организационные границы, роли, защита файлов и прикреплённого контента, приватность ответов, отзыв сессий и доступа |

Названия `LEARNHOUSE_*` в настройках и часть внутренних имён сохранены для совместимости с исходной платформой.

## Архитектура и сервисы

Учебное ядро — **модульный монолит FastAPI**. API, worker и scheduler используют общие модели и правила. Совместная доска и голосовой агент работают отдельными процессами.

~~~mermaid
flowchart TD
    Browser["Браузер"] --> Gateway["Nginx gateway"]
    Gateway --> Web["Next.js / React"]
    Gateway --> API["FastAPI /api/v1/tt"]
    Gateway <--> Collab["Hocuspocus / Yjs"]
    Browser <--> LiveKit["LiveKit Cloud"]
    API --> DB["PostgreSQL + pgvector"]
    API --> Redis["Redis / Celery"]
    API --> Files["Локальное content / S3-compatible"]
    API <--> Polar["Polar"]
    API --> AI["AI adapters"]
    Redis --> Worker["Worker"]
    Worker --> DB
    Worker --> AI
    Worker --> Mail["Resend"]
    Scheduler["Scheduler"] --> DB
    Collab --> API
    Voice["Voice agent"] <--> LiveKit
    Voice --> API
~~~

Локальный Compose запускает **восемь сервисов**, голос добавляется отдельным профилем:

| Сервис | Ответственность | Локальный доступ |
|---|---|---|
| `web` | Интерфейс, редактор, same-origin API/auth proxy | Через gateway |
| `api` | Учебные правила, роли, комнаты, контент и коммерческий доступ | `127.0.0.1:1349` |
| `worker` | Оценивание, авторинг, уведомления, платежные и другие фоновые задания | Внутри Docker |
| `scheduler` | Повторения, доставка outbox, напоминания, recovery и очистка | Внутри Docker |
| `collab` | Yjs-синхронизация досок и сохранение состояния | WebSocket через gateway |
| `db` | PostgreSQL 16 с pgvector | Внутри Docker |
| `redis` | Брокер, доставка событий, кеш и очередь сохранения досок | Внутри Docker |
| `gateway` | HTTP, API, SSE и WebSocket | `127.0.0.1:8096` |
| `voice-agent` | LiveKit Agents, распознавание участников и фасилитация | Опциональный профиль `voice` |

Neon, Cloudflare R2, Polar, Resend и LiveKit Cloud — внешние сервисы. Локальный Compose не поднимает их облачные аналоги.

## Учебное ядро

### Программа и публикация

Программа хранится как версия с blueprint, навыками и предварительными знаниями. У заданий есть семейство кейса, сложность, формат, правильные ответы, рубрика, объяснения и версия.

Поддерживаются закрытые ответы, множественный выбор, сопоставление и другие предусмотренные моделью форматы, а также оценивание рассуждений. Материалы, уроки, тренировочные задания, самостоятельные кейсы, диагностики и mock-формы имеют разные назначения.

Жизненный цикл контента:

~~~text
draft → review → approved → published → retired
~~~

Для полной программы проверяются покрытие blueprint, уроки по навыкам, самостоятельный банк и отдельные пробные экзамены. Банк должен сохранять минимум три свежих самостоятельных семейства на навык вне учебных упражнений, mock и опубликованных диагностик.

AI создаёт черновики. Завершение генерации не утверждает программу и не открывает продажи.

### Профиль и диагностика

Профиль включает цель, программу, дату экзамена, дневной бюджет, язык, IANA timezone и недельную доступность. Цель и расписание можно сохранить до появления доступной программы.

Предметная и когнитивная диагностика разделены. Для инструмента сохраняются версия, согласие и результаты. Открытые когнитивные ответы проверяет специалист с правом psychometric; они исключены из общего образовательного AI-grader, включая ранее поставленные в очередь задания.

Движок не является готовым валидированным тестом интеллекта. Методика, лицензия, условия проведения и допустимая интерпретация требуют утверждения специалистом. Короткая PMP-проверка не выдаётся за Gf/Gc или клиническую диагностику.

### Попытки и освоение

Отправленная попытка сохраняется отдельно: ответ, объяснение, подсказки, версия задания и условия выполнения. Повторная отправка с тем же ключом не создаёт вторую попытку. Экспертный пересмотр создаёт новую оценку и пересчитывает свидетельства с сохранением истории.

| Статус | Требования текущего алгоритма |
|---|---|
| `new` | Нет достаточного самостоятельного свидетельства |
| `developing` | Навык в работе |
| `independent` | Успешные независимые ответы в два разных дня, из двух разных семейств |
| `retained` | Дополнительная успешная проверка минимум через семь дней после переноса; минимум три дня и семейства |

Текущий порог успешной оценки — `score >= 0.8`. Последняя неудачная независимая попытка возвращает навык в работу.

Подсказки, Retell, ThinkFirst и встроенные упражнения урока считаются coached/assisted. Они полезны для обучения, но не устанавливают самостоятельное освоение. Просмотр материала и коллективный ответ учитываются отдельно.

### Today, повторения и дата экзамена

План учитывает срочные повторения, предварительные знания, пробелы программы, новые семейства и доступное время. Стартовые интервалы повторений — 1, 3, 7 и 14 дней; пересмотр оценки обновляет соответствующие назначения.

Расчёт даты использует timezone ученика и исключает день экзамена. Недельный план показывает доступное время. При `needs_content` оценка оставшейся нагрузки и требуемого темпа остаётся недоступной; это правило действует и в Why this plan.

Повторный GET без изменений не создаёт новую версию плана. Изменение цели, программы или бюджета приводит к пересчёту.

## Группы, занятия и голос

Постоянная группа содержит **4–6 реальных учащихся**. Совместимость проверяется по программе, языку, timezone, расписанию и экзаменационному окну. Группы не ранжируют участников по IQ; AI не заменяет реальных учащихся.

Сервер управляет фазами занятия:

~~~text
preparation → individual_attempt → discussion → transfer → summary
~~~

- Личные ответы и обратная связь скрыты до разрешённой фазы.
- Во время самостоятельной попытки и переноса закрыты обсуждение и помощь.
- Доска принимает изменения в preparation/discussion; после занятия доступна для чтения.
- Команды содержат ожидаемую ревизию; устаревшее состояние возвращает `409`.
- Чат и события поддерживают последовательности, replay и восстановление SSE.
- Обсуждения группы сохраняются между встречами; календарь доступен в JSON и ICS.

Для видео и голоса подготовлены LiveKit-токены, фазовые медиаправа и отдельный `apps/voice-agent`. Фасилитатор получает реплики с идентификатором участника и действует через ограниченные серверные команды. Он не может напрямую менять оценки, доступ, оплаты или членство.

Обработка речи требует согласия. Предусмотрен текстовый режим; аудио/видео по умолчанию не записываются. Расшифровки очищаются scheduler через 30 дней.

Реальное многопользовательское занятие через LiveKit Cloud ещё требует настроенных аккаунтов и отдельной приёмки.

## Два AI-конструктора курсов

Это два разных контура с разными провайдерами и результатами.

| Конструктор | Результат | Провайдер |
|---|---|---|
| **Create a course**, `content/generations` | Версия TT-программы, уроки и задания, история и checkpoints | Общий AI-адаптер или отдельный OpenRouter authoring |
| **Мини-курс из документа**, `content/course-pipeline` | Русский Markdown-курс, SVG-схемы, приватные артефакты и скачивание | Прямой DeepSeek API с отдельным ключом |

### Структурированный Create a course

Форма принимает тему, требования, текст и до пяти материалов. Основной file input поддерживает PDF, DOCX, TXT, Markdown, CSV и JSON; общий backend извлечения также умеет PPTX.

Текущий формат по умолчанию — `demo_three_chapters`:

1. Архитектор создаёт структуру трёх глав.
2. Агент урока пишет объяснение, пример, рефлексию и три места для упражнений.
3. Отдельный агент формирует структурированные упражнения.
4. Приложение создаёт RFC4180 CSV, проверяет ключи, ссылки, формулы и маркеры.
5. Упражнения превращаются в реальные TTItem и вставляются в урок.
6. После восьми checkpoints сохраняются **три урока и девять упражнений** со статусом `ready for review`.

Используются блоки `:::explain`, `:::example`, `:::reflection`, `:::exercise` и проверяемые ссылки на материалы. Маркеры внутри fenced code сохраняются как код.

В истории доступны промежуточные главы, предпросмотр, CSV, retry и остановка после текущего шага. SSE имеет polling fallback. Обновление страницы не создаёт новый запуск.

Явный API-режим `full_pmp` предусматривает 26 навыков, учебные и тренировочные материалы, два непересекающихся mock-экзамена и 64 шага. Это режим подготовки черновика, а не уже утверждённая полная программа. Психометрические инструменты AI-конструктор не создаёт.

### Русский мини-курс

Отдельный интерфейс принимает PDF с текстовым слоем, TXT, Markdown, DOCX и PPTX. Создаёт русский курс из трёх глав с SVG-схемой для каждой главы и скачиваемыми Markdown-артефактами.

У него собственный pipeline и `DEEPSEEK_API_KEY` официального DeepSeek API. Ключ OpenRouter этот контур не настраивает. Модель в текущем коде — `deepseek-flash`.

Результат этого конструктора не превращается автоматически в опубликованную TT-программу с TTItem.

### Ограничения загрузки

- До 10 МБ на файл и до двух миллионов извлечённых символов.
- PDF должен содержать текстовый слой. OCR и EPUB не реализованы.
- Для большой книги выбираются фрагменты; весь текст не отправляется одним запросом.
- Ссылки и короткие цитаты проверяются по извлечённым материалам.
- Фактологию, методику и права использования проверяет эксперт.

Контракты: [COURSE_FORMAT.md](docs/thinktogether/COURSE_FORMAT.md), [AI_AUTHORING.md](docs/thinktogether/AI_AUTHORING.md), [COURSE_PIPELINE_RU.md](docs/thinktogether/COURSE_PIPELINE_RU.md).

## Настройка AI

Все ключи задаются на сервере в локальном `.env` или secret-хранилище окружения. Для совместимости используются существующие имена настроек LMS.

### Общая генерация через OpenRouter

Пример конфигурации, с которой проверялась генерация DeepSeek:

~~~dotenv
LEARNHOUSE_IS_AI_ENABLED=true
LEARNHOUSE_AI_PROVIDER=openrouter
LEARNHOUSE_AI_API_KEY=<your-server-side-openrouter-key>
LEARNHOUSE_AI_MODEL_FAST=deepseek/deepseek-v4.1-flash-1017
LEARNHOUSE_AI_MODEL_STANDARD=deepseek/deepseek-v4.1-flash-1017
LEARNHOUSE_AI_MODEL_PRO=deepseek/deepseek-v4.1-flash-1017
TT_REASONING_MODEL=deepseek/deepseek-v4.1-flash-1017
TT_FACILITATOR_MODEL=deepseek/deepseek-v4.1-flash-1017
~~~

Это зафиксированный пример модели, использованной в проверке; доступность и стоимость выбранной модели определяются провайдером. Сохранился также Google/Gemini-адаптер.

Для отдельной настройки только авторинга:

~~~dotenv
TT_CONTENT_ENABLED=true
TT_CONTENT_PROVIDER=openrouter
TT_CONTENT_API_KEY=<your-server-side-openrouter-key>
TT_CONTENT_MODEL=deepseek/deepseek-v4.1-flash-1017
~~~

Без отдельного provider override авторинг использует общий AI. Для модели авторинга нужен `TT_CONTENT_MODEL` либо fallback `TT_REASONING_MODEL`.

### Embeddings через совместимый endpoint

Для OpenRouter embeddings используется OpenAI-совместимый адаптер и общий `LEARNHOUSE_AI_API_KEY`:

~~~dotenv
LEARNHOUSE_AI_BASE_URL=https://openrouter.ai/api/v1
LEARNHOUSE_AI_EMBEDDING_PROVIDER=openai
LEARNHOUSE_AI_EMBEDDING_MODEL=openai/text-embedding-3-small
LEARNHOUSE_AI_EMBEDDING_DIMENSIONS=768
~~~

Генерация изображений, TTS и отдельный русский мини-курс имеют собственные настройки. Один ключ общего текстового AI не включает все эти функции.

### Остальные внешние подключения

| Подключение | Основные настройки |
|---|---|
| Русский мини-курс | `DEEPSEEK_API_KEY` |
| LiveKit | `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, AI фасилитатора |
| Resend | `LEARNHOUSE_RESEND_API_KEY`, `LEARNHOUSE_SYSTEM_EMAIL_ADDRESS` |
| Polar | `TT_POLAR_ENVIRONMENT`, `TT_POLAR_ACCESS_TOKEN`, `TT_POLAR_WEBHOOK_SECRET`, `TT_POLAR_SUCCESS_URL` |
| Google OAuth | `LEARNHOUSE_GOOGLE_OAUTH_CLIENT_ID`; предусмотрен alias `LEARNHOUSE_GOOGLE_CLIENT_ID`; требуется настройка OAuth-приложения и callback |
| Production DB/storage | Отдельная PostgreSQL/Neon-конфигурация и S3-compatible/R2-хранилище |

## Оплаты и доступ

Коммерческий контур ThinkTogether реализован самостоятельно поверх Polar и не зависит от приватного платежного модуля LMS Enterprise.

1. Ученик заполняет профиль и проходит необходимые диагностики.
2. Сервер проверяет подходящую действующую группу и свободное место.
3. На checkout создаётся резерв места на **30 минут**.
4. Polar подтверждает заказ через проверенный webhook и серверную сверку.
5. Транзакция активирует доступ и членство в группе.

Возврат браузера со страницы оплаты показывает состояние заказа; сам redirect доступ не выдаёт.

Webhook сохраняется в inbox с уникальным идентификатором. Дубли и изменение порядка событий обрабатываются повторяемо; состояние сверяется с авторитетным заказом. Поздняя оплата повторно проверяет место. Если зачисление невозможно, ставится полный возврат.

Полный возврат отзывает доступ и членство; частичный учитывается отдельно. Повтор возврата сначала проверяет оставшуюся возвратную сумму. Периодическая сверка восстанавливает пропущенные события.

Ограничения распространяются на прикреплённые материалы LMS, файлы, поиск/RAG, комнаты, доски и медиатокены. Обычные публичные курсы исходной LMS автоматически платными не становятся.

## Надёжность и безопасность

- **PostgreSQL — источник истории.** Попытка и фоновое событие записываются транзакционно; Redis доставляет задания.
- **Durable jobs.** Уникальные ключи, leases, retry/dead-состояния и scheduler recovery защищают записи БД от повторных эффектов.
- **Внешние вызовы.** При восстановлении задания запрос к LLM или другому провайдеру может повториться. Гарантия exactly-once для внешнего API не заявляется.
- **Совместная доска.** Dirty snapshots, retry и CAS сохраняют правки при сбоях API; Redis backlog участвует в восстановлении.
- **Сессии.** Укреплены auth proxy, CSRF, проверка host/origin, обработка cookie, MFA/refresh и немедленный отзыв access/refresh при logout.
- **Границы доступа.** Организация, роль, группа, entitlement и фаза комнаты проверяются сервером. Generic API token не заменяет интерактивную TT-сессию.
- **Приватность.** Личные ответы, score/evaluation и когнитивные результаты скрыты от чужих участников и общего образовательного AI.
- **Наблюдаемость.** Есть учёт расходов AI и структурированные события без копирования ответов и секретов в usage-логи.
- **UTC.** Время событий сохраняется как UTC; расписание дополнительно хранит IANA timezone.

В учебном ядре **42 таблицы с префиксом `tt_`**. Текущая цепочка миграций:

~~~text
tt_20261114_01 → tt_20261115_02 → tt_20261115_03
~~~

Вторая ревизия добавляет обсуждения группы, третья переводит временные метки staff grant, audit event и notification в PostgreSQL TIMESTAMPTZ.

## Последние исправления

Помимо исходной реализации, в текущий код вошли:

1. UTC-aware записи выдачи прав, аудита и уведомлений с отдельной миграцией.
2. Повторная SSE-авторизация после rollback без обращения к истёкшему ORM-кешу.
3. Сохранение новых правок доски при недоступности API: snapshots, retry и CAS.
4. Скрытие личных ответов **и** score/evaluation до разрешённой фазы.
5. Точный отзыв сессий при logout, включая операции внутри одной секунды.
6. Доступные инструменты рисования и заметок в узком iframe доски.
7. Сохранение CSV-плейсхолдеров внутри fenced code как обычного текста.
8. Возврат индивидуального `completed_at` урока в списке и после reload.
9. Рабочее отображение marker-only упражнения без сырого `{{item:...}}`.
10. Частичный профиль без программы, дата по timezone, стабильная версия Today и честное отображение нехватки контента.
11. Home/логотип и размещение учебной навигации в More → Core.
12. Исправление Tiptap: новые страницы создаются корректным документом, старый корневой `{}` нормализуется перед редактором. Вложенные атрибуты, HTML, фрагменты и существующие виджеты сохраняются.

Последний пункт проверен настоящим Tiptap в регрессионном тесте и реальными кликами: новый закрытый курс → Dynamic Page → текст → Save → обновление страницы. Текст сохранился; предупреждений и ошибок в консоли редактора не было.

## Локальный запуск

### Требования

- Git, Docker с Linux containers и BuildKit.
- PowerShell **7** и доступный `tar`.


Скрипт создаёт `docker/thinktogether/.env` с отдельными случайными секретами. Существующий файл сохраняется. Данные начального администратора находятся в этом файле; пароль не публикуется в README.

Основные адреса:

- Приложение: [localhost:8096](http://localhost:8096/).
- Today: [localhost:8096/thinktogether/today](http://localhost:8096/thinktogether/today).
- Эксперт: [localhost:8096/thinktogether/expert](http://localhost:8096/thinktogether/expert).

- Health через gateway: [localhost:8096/api/v1/health](http://localhost:8096/api/v1/health).

Порты по умолчанию привязаны к loopback. Отдельная контрольная установка на 8095, использовавшаяся при разработке, не является частью этого Compose.

## Сборка, обновление и миграции

Из корня репозитория:

~~~powershell
docker compose @ttCompose build api collab
pwsh -NoProfile -File ./scripts/bundle-thinktogether-source.ps1
docker compose @ttCompose build web
docker compose @ttCompose up -d --wait --wait-timeout 300
~~~

Перед финальной web-сборкой нужно обновлять соответствующий source archive, включая изменения API и документации. В приложение включается скачивание `/thinktogether-source.tar.gz`. Внутрь не должны попадать `.env`, runtime-данные и резервные копии.

Локальный Compose выбирает Webpack через `TT_NEXT_BUILD_BUNDLER`, по умолчанию `webpack`. Общий Dockerfile также поддерживает Turbopack. Для локального Webpack включены ограничение heap и настройки уменьшения памяти. Web-сборки следует выполнять последовательно.

Проверка миграций:

~~~powershell
docker compose @ttCompose exec -T api /app/api/.venv/bin/python cli.py migrate --status
~~~

В production миграции выполняются явно перед обновлением сервисов. `LEARNHOUSE_AUTO_MIGRATE=false` в production-конфигурации исключает автоматическое изменение схемы при запуске API.

### Резервная копия и проверка восстановления

~~~powershell
pwsh -NoProfile -File ./scripts/thinktogether-backup-restore.ps1
~~~

Локальный скрипт создаёт dump и JSON-отчёт, восстанавливает отдельную временную БД, сравнивает public row counts и Alembic revision. Результаты лежат в игнорируемом каталоге `.learnhouse/thinktogether-backups`. Для точного сравнения нужен период без конкурентных записей.

Эта проверка относится к локальному PostgreSQL. Проверка Neon PITR и восстановления объектов R2 выполняется отдельно.

### CI

[ThinkTogether integration](.github/workflows/thinktogether.yaml) запускается на **pull request** и **workflow_dispatch**:

- API, PostgreSQL-инварианты и migration round trip.
- Голосовой образ и детерминированные тесты.
- Collab-тесты и production-образ.
- Web production-образ, сборка source archive и сравнение SHA-256 архива внутри образа.

Обычный push сам по себе этот workflow не запускает. Полный Bun web suite запускается отдельно; текущий web job проверяет сборку и соответствующий исходный код. Результаты локальных прогонов не являются заявлением о зелёном GitHub Actions run.

## Production и условия открытия продаж

Подготовлены `docker/thinktogether/production.compose.yml` и production env-шаблоны. Это самостоятельный deployment, а не override локального Compose.

Предусмотрены собственные immutable-образы (`TT_IMAGE_PREFIX`, `TT_RELEASE`), отдельный `TT_ENV_FILE`, внешний PostgreSQL, S3-compatible storage, private Redis, worker, scheduler, collab, gateway и voice-agent. Для миграций используется `TT_MIGRATION_DATABASE_URL`; для runtime — `LEARNHOUSE_SQL_CONNECTION_STRING`.

Новая пустая production-БД требует bootstrap исходной LMS и миграций. Одного upgrade head недостаточно. Порядок релиза, операции с уже установленной БД и recovery описаны в [RUNBOOK.md](docs/thinktogether/RUNBOOK.md).

### Что ещё нужно до платного пилота

- Полный авторский или лицензированный PMP-курс, проверенные рубрики, самостоятельный банк, отсроченные проверки и два изолированных mock-банка.
- Лицензированный когнитивный инструмент и утверждённая специалистом интерпретация.
- Реальные совместимые группы и работа оператора.
- Production-аккаунт Polar, продукты, webhook и проверенные checkout/refund/reconciliation в staging.
- LiveKit Cloud, реальные многопользовательские занятия и согласия.
- Почта, закрытое хранилище, домен, TLS и наблюдаемость.
- Минимум 100 настоящих экспертных разметок и разбор расхождений AI-оценивания; целевой допуск версии — 90% совпадения зачтено/не зачтено.
- Проверка восстановления production-БД и файлов, нагрузка и операционная поддержка.
- Явное разрешение выпуска.

Checkout закрывается до verified email, учебной готовности, утверждённого полного non-sample курса, инструментов, продукта и реальной подходящей группы. Технические release gates включают `TT_RELEASE_APPROVED`, `TT_AI_EVALUATION_APPROVED`, `TT_RESTORE_DRILL_PASSED`; для production Polar — `TT_POLAR_PRODUCTION_APPROVED`. Эти флаги выставляются по полученным подтверждениям.

Подготовка к PMP не означает автоматическую выдачу официальной сертификации или признание учебных часов PMI.
